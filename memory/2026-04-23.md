## Claude Code + LM Studio Proxy - aiohttp 重写完成（23:26-23:32）

**问题根源：** Flask dev server 在 Windows 上会 buffer 整个 generator response，导致 streaming 响应只有最后的 message_stop event，前面的 content_block_delta 全丢失。

**解决方案：** 用 aiohttp 重写代理（`claude_lm_proxy.py`），aiohttp 的异步迭代器不做 buffering。

**关键修改点：**
- `async with session.post(... )` 异步迭代 `resp.content` 逐行读取
- `content_block_start` 改为按需发送（第一个 content delta 时才发）
- `message_stop` 在 streaming 结束后才发送
- 统一使用 utf-8 解码（`errors='replace'`）

# 2026-04-23 日志（压缩前最终追加 - 23:35）

## Claude Code + LM Studio Proxy - 最终发现 aiohttp 修复（23:32-23:50）

**问题演进时间线：**
1. Flask + stream generator → Windows buffering → 只有 message_stop 到达客户端
2. 换 aiohttp 后 streaming 仍有问题 → 500 错误
3. **最终根因（23:50 发现）：** `ClientSession` 复用导致连接池状态损坏
   - `get_session()` 返回同一个 session 实例
   - streaming 响应未完全消费时连接被归还池中
   - 下次复用该连接时读取到损坏的状态 → 500 error

**修复方案：** 每次请求创建独立 `aiohttp.ClientSession`（`async with session` 方式），不复用 session。

**已验证工作的最小代理代码（`_test_lm_passthrough.py`）：**
```python
async with aiohttp.ClientSession(timeout=aiohttp.ClientTimeout(total=60)) as session:
    async with session.post('http://localhost:1234/v1/chat/completions', json=openai_data) as resp:
        async for line in resp.content:
            if line:
                await response.write(line)
```

**关键教训：** aiohttp 的 `ClientSession` 在流式场景下不应跨请求复用。non-streaming 可以复用，streaming 必须每次新建。

**代理文件待更新：** `claude_lm_proxy.py` 需要将 `get_session()` 改为每次 `async with aiohttp.ClientSession()` 新建 session。
